# v0.1.12 — 不再「工具说成功、配置被静默丢弃」

## 1. 现场

下游报的（2026-10-26），环境是 DSH 0.2.1-rc.2 桌面版 / Windows / `link:` 安装：
**代码已经拉到磁盘，但 GUI 进程里跑的还是上一版**（进程启动时间早于 `git pull`）。此时调用：

```json
{ "perDay": 6, "guaranteeKeywords": ["dsh 插件", "DeepSeek"] }
```

返回：

```json
{
  "ok": true,
  "host": { "ok": false, "error": "Config field \"guaranteeKeywords\" is not volatile" }
}
```

实际结果：

- `config.json` 里 `perDay` 变成了 6（生效）；
- `guaranteeKeywords` **根本不在文件里**（被静默丢掉，没有报错、没有日志）。

不是 0.1.11 的 bug，是版本错位的窗口期问题。但**错位的时候工具不该说 `ok: true`**。

## 2. 三个毛病，一起改

### a) 顶层 `ok` 跟着真相走

以前 `bili_config` 恒回 `ok: true`，`host` 写在里面也没人看。现在：

| 情况 | 返回 |
|---|---|
| 都生效 | `ok: true` |
| 有不认识的键 / 宿主拒收 | `ok: false` + `warn`（人话原因）+ `ignored`（点名的键） |

### b) 被丢掉的键必须点名

「静默丢弃」这个兼容策略本身没问题（旧进程不认识新键，只能丢），但**至少要留一条日志**。
现在三处都有：

- 返回值 `ignored: ["guaranteeKeywords"]`；
- `warn`：「这些设置键这一版不认识，已经被丢掉：guaranteeKeywords（多半是插件代码更新了、
  但 DSH 进程还在跑旧版 ⇒ 重启 DSH 再存一次）」；
- `duty.log` 一行 `⚠️ 这些设置键这一版不认识，已经丢掉了：…`。

顺带补了 HTTP 那条路：`POST /api/bili-duty/config` 有一份字段白名单，白名单外的键以前也是
静默丢的，现在同样计入 `ignored`。

### c) `host` 从两种表示法改成四态

以前只读调用回 `host: null`，写成功回对象 —— 成功 / 失败 / 未就绪三种状态用了两种表示法。
现在 `host.state` 一定是这四个之一：

| state | 含义 |
|---|---|
| `synced` | 宿主设置页那份也写进去了 |
| `rejected` | 本地 `config.json` 写了，宿主拒收（旧 schema 不认新键 / revision 过期 / 回读不一致） |
| `skipped` | 没有需要同步的键（只给了 `githubToken`，宿主持久化不存 token；或 patch 为空） |
| `not-written` | 这次没给 `patch`（只读）—— 不是失败，也不是成功，就是没写，另带 `hint` |

`ok` 只是 `host.state` 的布尔投影（`not-written` 时 `ok` 仍是 true）。

## 3. 还有一个更隐蔽的连带伤害

旧宿主收到不认识的键时是**整批拒收**的 —— 也就是说 `perDay` 其实也没同步进设置页，
只是 `config.json` 那份兜住了它。所以这一版还做了一件事：

> **不认识的键不再发给宿主**：先在本地分一次手，认识的键照常写、照常同步。

结果是同一批里认识的键能真正同步成功，不认识的键单独被点名，而不是互相拖累。

## 4. 自检

```powershell
node scripts/audit-config.mjs --strict   # 37 键 / 37 消费点，12 占位符 / 12 fill，0 条 ⚠️
node scripts/prompt-smoke.mjs            # A-E + F1-F3 全过
node scripts/smoke-apply.mjs             # 6 条全过（新增 [5/6] [6/6]）
node scripts/verify-host.mjs             # 宿主依赖可达
```

新增的两条断言就是照现场写的（用 `someFutureKey` 模拟「进程还是旧版」）：

- `[5/6]` HTTP 这条路：未知键 ⇒ `ok: false`、`ignored` 点名、`perDay` 照样写进去、
  `host.state === "synced"`（未知键没混进 patch，所以宿主不拒收）；
- `[6/6]` 工具这条路：只读 ⇒ `ok: true` + `host.state === "not-written"`；
  混合 patch ⇒ `ok: false` + `ignored`；只给认识的键 ⇒ `ok: true` + `synced`。

## 5. 升级

```powershell
dsh plugin --profile web add github:Parirose/dsh-bili-github-brief
```

升完**必须重启 DSH** —— 这一版修的正是「代码换了、进程没换」时的观感，
你自己的机器如果没重启，看到的还是旧行为。
