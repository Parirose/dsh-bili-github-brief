# v0.1.11 — 保底关键词组

## 1. 为什么加它

2026-10-26 实测：`perDay = 5` + 14 个关键词 ≈ 200 条候选抢 5 个位置。
搜「dsh 插件」这一组 `count = 15`，里面有好几条**当天新发、高度相关**的内容
（省 token 插件到底能不能省、把 dsh 接进 QQ bot、超详细的 DSH 安装与插件整合），
但正文里一条都没有。原因不是没搜到，是三件事叠在一起：

1. 硬上限只有 5 个位置；
2. 提示词把日报定义成「AIGC 日报」，评分表「领域相关度 35%」让非 AIGC 内容天然吃亏；
3. dsh 类视频多为短更新通知，容易在「标题党 / 低质」过滤里被误伤。

## 2. 怎么用

面板「关注什么」里多了一个输入框，或直接改配置：

```json
{ "perDay": 6, "guaranteeKeywords": ["dsh 插件", "DeepSeek"] }
```

- 这一组**每轮至少挑 1 条、最多挑 2 条**进 B站 正文；
- **占 `perDay` 的名额**，不是额外加量（`perDay = 5` + 保底 2 条 ⇒ AIGC 那边只剩 3 个位置）；
- 留空 = 不启用，行为和以前完全一样；
- 面板里是**一行一个**（不是逗号分隔）。

报告里每条 B站 内容多了一行 `- 分组：保底 / AIGC`，QQ 版里保底条目排在最前、标题行前加 `[保底] `。

一条合格的都没有时，必须写进「## 数据缺口」：

```text
- 保底组候选 4 条，全部不达标，原因：3 条是直播回放，1 条只有标题没有内容
```

**不许**为了让保底组有内容，把标题党 / 纯搬运 / 直播回放 / 明显无关的条目塞进正文 ——
宁可空缺并说明。这条写进了提示词的规则文本里，不是靠自觉。

## 3. 规则文本是生成的，不是模板里写死的

模板 `prompts/brief-prompt.txt` 里只有一个占位符：

```text
今天已经挑过 {{ALREADY}} 条 ⇒ 这一轮最多再挑 {{LEFT}} 条；挑够就停，剩下的明天再说。

{{GUARANTEE_BLOCK}}
```

文本由 `lib/prompt.mjs` 的 `renderGuaranteeBlock(list, perDay, left)` 生成，三种分支：

| 情况 | 渲染结果 |
|---|---|
| `guaranteeKeywords` 为空 | 一句中性说明（「这一轮没有设保底关键词组，所有关键词统一排序。」） |
| 有名额 | 完整配额规则：至少 1 条、最多 2 条、占名额、分组标记、缺数据怎么写、不许凑数 |
| `left = 0`（额度已用完） | 说明这一轮保底组不挑 —— **不会**再说「至少挑 1 条」 |

最后一行是这一版专门补的：`left = 0` 时还写「至少挑 1 条」，会和同一节上面的
「这一轮最多再挑 0 条」直接打架，模型只会挑一个服从。

## 4. 顺带：提示词模板其实早就会自动对齐

施工单里担心「家里那份 `brief-prompt.txt` 是手工放的、没人同步，改了仓库也不生效」。
查下来不用改代码也不用写手工命令 —— `index.js` 的 `apply()` 里本来就有：

```js
ensureHomeFiles(pluginDir, stateDir, log)   // 每次启动都跑
```

`lib/state.mjs` 里 `brief-prompt.txt` 在 `ensureHomeFiles` 的拷贝清单里，且 `overwrite = true`：
**内容不同就覆盖家目录那份**。所以「升级 + 重启 DSH」之后，家里那份自动就是新模板。

代价要说清楚（已写进 `docs/CONFIG.md`）：**改家目录里那份副本会被重启打回去**。
想改规则就改仓库里那份再重新安装。真要做「用户可改的模板」，得像 `ensureCharter` 那样加
sha256 账本（改过就另存 `.new` 让人自己合），那是另一件事，这一版没动。

## 5. 顺手修的一句假信息

面板「读不到插件配置」的提示原本写着「装的还是 0.1.11 / 0.1.12（那两版有 bug，会卡在这里）」——
这两个版本号从来没发布过（tag 只到 v0.1.10），而 0.1.11 正是这一版。已换成不依赖版本号的说法。

## 自检

```powershell
node scripts/audit-config.mjs --strict   # 37 键 / 37 消费点，12 占位符 / 12 fill，0 条 ⚠️
node scripts/prompt-smoke.mjs            # A-E + F1-F3 全过
node scripts/verify-host.mjs             # 宿主依赖可达
```

F 系列断言（保底规则渲染、空组只给中性句、额度为 0 时不硬要 1 条）都做过反向验证：
把 `{{GUARANTEE_BLOCK}}` 从模板里删掉 ⇒ F1a/F1c 红；把 `renderGuaranteeBlock` 的空数组分支
改成返回完整规则 ⇒ F2b 红。

## 升级

```powershell
dsh plugin --profile web add github:Parirose/dsh-bili-github-brief
```

升完重启 DSH（重启时家目录那份提示词模板会自动换成新的）。不需要重装 Python 依赖，
也不需要重装 NapCat 插件。
