# v0.1.3 — headless 模型继承 / 打包版 dsh 探测 / uv 下载超时

这是 `v0.1.2` 之后的修复版，解决三个会让核心功能跑不起来的缺陷。

## Fixed

- `ensureOverlay()` 不再写死作者本机的 provider
  - 删除 `llm-pi-ai` / `agent-default-model` 两段
  - 不再覆盖 `wb-proxy` / `WB_PROXY_API_KEY` / `127.0.0.1:8788`
  - headless 直接继承 profile / home 层的模型配置
  - 保留 `credentials` / `authorization` / `deepseek-account` 与 MCP insert
- `findDshCli()` 能直接找到 Electron 打包版里的 dsh
  - 先探测 `<resources>/app.asar/node_modules/@deepseek-ai/dsh/lib/bin.js`
  - 再探测 `app.asar.unpacked`
  - 不再依赖递归扫描；`app.asar` 在文件系统里是文件，`Dirent.isDirectory()` 为 false
- uv 下载不再永久挂起
  - 主下载加 `AbortSignal.timeout(120000)`
  - sha256 / PyPI 查询加 30 秒超时
  - 失败/超时写入原因和手工兜底命令
- `bili_setup` 支持强制复位卡住的 `installing`

```json
{"force": true}
```

- 优先复用宿主自带 uv
  - `<resources>/app.asar.unpacked/node_modules/@dataiku/uv-*/bin/uv.exe`
  - 然后探测 `%LOCALAPPDATA%\uv`、`%USERPROFILE%\.cargo\bin`、`%USERPROFILE%\.local\bin`、PATH
  - 最后才下载

## Added

- `docs/TROUBLESHOOTING.md`：补手工建 venv、依赖判定条件和 `bili_setup force` 用法
- 手工兜底命令会写进 `install.log`

## 安装 / 升级

### 标准 web profile

```bash
dsh plugin --profile web add github:Parirose/dsh-bili-github-brief
```

装完重启 DSH。

### DSH 桌面版（Electron）

```powershell
$env:ELECTRON_RUN_AS_NODE = '1'
& 'C:\DSH NEXT\DSH NEXT.exe' 'C:\DSH NEXT\resources\app.asar\lib\plugin-cli.js' `
  desktop add "link:D:\path\to\dsh-bili-github-brief"
```

装完重启 DSH NEXT。

第一次跑一轮前，先初始化 headless profile：

```powershell
& '<app>/DSH NEXT.exe' '<app>/resources/app.asar/lib/plugin-cli.js' headless list
```

## 验证

```powershell
node scripts/verify-host.mjs
```

期望：

```text
[1/4] bundle 挂载声明
[2/4] client 注册 id
[3/4] 命名空间（id <-> export const name）
[4/4] 宿主依赖
结果：全部通过
```

如果装依赖卡住，先调用：

```json
{"force": true}
```

然后查看 `<DSH_HOME>/bili-duty/install.log`。
