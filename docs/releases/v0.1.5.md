# v0.1.5 — 修 0.1.4 冷启动 TDZ（设置面板读不到配置）

## 必升

0.1.4 有一个**必崩**的初始化顺序错误，0.1.5 修复。**请务必升级。**

### 现象

- DSH 日志里出现 `1 entry did not activate`
- 设置页「刷B站」面板一直「读不到插件配置」
- `/api/bili-duty/*` 全部是 404（插件根本没激活）

### 原因

`index.js` 的 `loadCfg()` 里，`applyLegacyQQBackend()` 引用了 `touched`，
而 `touched` 的 `const` 声明在它后面（TDZ）。冷启动时 Settings 服务尚未就绪，
`settingsDesc()` 返回 `null`，于是先走 `if (!row) return clampPatch(applyLegacyQQBackend(saved, {}))` ⇒

```text
ReferenceError: Cannot access 'touched' before initialization
```

⇒ 整条插件没激活。

### 修法

`ov` 与 `touched` 两段（连同注释）整体上移到 `const row = settingsDesc()` 之后、
`applyLegacyQQBackend` 之前；原位置留一行注释。行为与 0.1.4 完全一致，只是声明顺序对了。

### 新增回归测试

```powershell
node scripts/smoke-apply.mjs
```

用假 ctx 真跑一遍 `apply()`，覆盖四条路：

1. 冷启动（`settings.describe` 不存在）
2. 老配置兼容（只有 `qqForwardUrl` ⇒ `napcat-plugin`）
3. 用户显式选 `off` 不被改回
4. Settings 已就绪（有 row）

`node --check index.js` 只查语法，查不出这种运行时错误；以后改 `loadCfg()` 都跑一下它。
