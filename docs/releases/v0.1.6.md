# v0.1.6 — 修 smoke-apply 在 Windows 上的假失败

## 这一版只改自检脚本

插件本身行为**没有任何变化**；修的是 v0.1.5 新加的自检脚本
`scripts/smoke-apply.mjs` 在 Windows 上的误报。

### 现象

Windows 上跑 `node scripts/smoke-apply.mjs`：

```text
[1/4] 冷启动（Settings 服务未就绪，row = null）
  FAIL apply() 抛异常：ENOTEMPTY, Directory not empty: ...\Temp\dsh-smoke-cold-xxxx
[2/4] OK   [3/4] OK   [4/4] OK
结果：失败 1 项（退出码 1）
```

但插件完全正常——同一个目录下一轮再跑就过了。

### 原因

`runOnce()` 的 `finally` 用 `fs.rmSync(home, { recursive: true, force: true })` 清临时目录，
但 `apply()` 刚往里面铺过 `mcp_server.py` / `brief-prompt.txt` 等文件。
Windows 上删除会和**写入句柄 / 索引 / 杀软扫描** 抢文件 ⇒ `ENOTEMPTY` / `EBUSY`。
这个异常从 `finally` 抛出去，就被外面的 catch 当成「apply() 抛异常」。

### 修法

```js
try {
  fs.rmSync(home, { recursive: true, force: true, maxRetries: 10, retryDelay: 150 })
} catch (e) {
  console.warn('  （临时目录没清干净，忽略：' + (e?.code || e?.message) + '，路径 ' + home + '）')
}
```

- `maxRetries` / `retryDelay` 是 `fs.rmSync` 自带的 Windows 重试参数（不自己写循环）；
- 清理失败**只 warn，不计入失败项**；
- 异常措辞改成「apply() 真崩了（<code>：<message>）」，与清理夺开。

### 验证

```text
node scripts/smoke-apply.mjs   连跑三次 → 三次都「全部通过」，退出码 0
$env:TEMP\dsh-smoke-*        → 没有残留
```

并且**故意锁住**临时目录里的文件模拟 Windows 抢文件，复现了真实路径：

```text
  （临时目录没清干净，忽略：EPERM，路径 ...\dsh-smoke-cold-xxxx）
  OK   /api/bili-duty 路由挂上了
  ...
结果：全部通过（apply() 冷启动不崩）
```

⇒ 即使真清不干净，自检也不会再假报失败。
