# v0.1.7 — bili_subtitle 对瞬时 TLS 失败自动重试

## 修什么

`bili_subtitle` 之前一遇到 TLS 信任失败就直接返回 `tls_untrusted_ca`，
但 2026-10-25 实测发现：**同一台机、同一个 venv、同一分钟内**，最开始两次报错，
之后 7 次全部成功——不是根证书缺失，是信任存储（truststore / OS 根存储）的**瞬时抖动**。

危害不只是“少一条字幕”：模型会把这次偶发当成全局故障，在中间推理里写下
“字幕接口 SSL 全失败、0 条字幕”。上一轮报告最终写对了，但过程确实被带偏。

### 改法

1. **TLS 异常自动重试一次**（0.6s 间隔），仅限 TLS 类错误；
   其它异常（接口报错、网络断）不重试，立即上抛。
2. **信任链兜底**：下载字幕时先用默认 context（装了 `pip-system-certs` 就是 OS 根存储），
   TLS 失败就换 `ssl.create_default_context(cafile=certifi.where())` 再试一次。
3. 持续失败时的 `hint` 改成「已重试仍失败：要么没装 pip-system-certs，要么这台机器缺根证书」。

### 验收（本机实测）

- 连续 10 条 B站视频：**7 条拿到字幕**（262～515 段不等）、2 条本来就没有字幕、1 条稿件已不可见（62002，
  与 TLS 无关）；**`tls_untrusted_ca` 出现 0 次**。
- 单元测试：“抖一次后成功”→ 第 2 次拿到字幕；“一直失败”→ 结构化错误 + 新提示；
  “非 TLS 错误”→ 只试 1 次。
- 信任链对比：同一个 `aisubtitle.hdslb.com` 字幕 URL，默认 context 与 certifi **都是 HTTP 200**。
