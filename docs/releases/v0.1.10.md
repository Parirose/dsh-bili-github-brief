# v0.1.10 — 人设有了落点 / 超限告警说实话 / 家目录可隔离

## 1. 人设终于能“落到报告里”

上一版已经把 `AGENTS.md` 塞进提示词了，但实测发现输出还是机构口吻（「## 今日结论」
「- **我的判断**」）—— 人设读到了、配额也执行了，只是**没有落点**，且被第一行
「你是我的 B站 + GitHub AIGC 情报员。」压住了。

### 改了什么

- **身份让位**：模板开头现在是

  ```text
  {{OWNER_DOC}}

  ⭐ 上面那份设定只影响**语气和称呼**。本文件后面的规则…一律优先

  先按上面那份设定进入身份，**然后以这个身份**完成今天的 B站 + GitHub AIGC 日报。
  ```

  并**删掉**原第一行「你是我的 B站 + GitHub AIGC 情报员。」（它和设定里的「你是亚托莉」
  直接冲突，且位置更靠前 —— 模型会优先服从它）。

- **语气加了硬落点**：在「## 今日结论」下写明“这一节和 QQ 版开头必须用设定里那个身份的口吻写，
  该有的自称 / 称呼 / 口癖至少各出现一次；但链接、Stars、日期、数字这些事实字段照旧中性”。
  QQ 版也要求“第一段用那个身份的口气开场”。
- **写完自查**：把两处单独读一遍，读不出那个人的口气就重写，而不是加一句解释。

> “口吻到不到位”只能人工判，没写成自动断言；但“身份声明不许回来、人设必须在身份句之前、
> 两处语气要求必须在”三件事已经写成断言（E1～E4）。

## 2. 「超出每日上限」不再假报

两个毛病：

- 旧文案说“**报告里** X 条”，但 X 实际是**全天累计**（只增不减）—— 实测那轮报告只有 5 个
  `### BV`，日志却说“报告里 10 条”，排查被带偏；
- “已按上限关注前 N 条”是**假的** —— 插件从来没裁剪过内容。

现在分开报：

```text
⚠️ 超出全天额度：今天累计 10 条 > perDay 5（本次报告 5 条；累计只增不减，模型主动收敛也不还额度）
```

QQ 版末尾也改成“今天累计已挑 M 条，超过上限 N；本次报告 K 条”，不再说“已按上限关注”。

## 3. 家目录可隔离（默认关，老用户零迁移）

同一台机器上同时跑桌面版与 web 版时，不应共用 `$DSH_HOME/bili-duty/`。
给其中一边填：

```json
{ "stateDir": "bili-duty-web" }
```

- 只认**单层目录名**（带 `/` `\` 就当没填，防路径注入）；
- 默认空 ⇒ 路径与以前完全一致，**不会搬家**；
- 改完要重启 DSH（运行中改它只会记一行提示）；
- `state.json` 现在带心跳 `host{pid,profile,at}`，5 分钟内另一个宿主还在跑就会跳过这一轮。

## 4. 跨宿主（非桌面）的四个小缺口

- 「打开文件夹」：现在 Windows / macOS（`open`）/ Linux（`xdg-open`）都能用；
- `docs/INSTALL.md` 新增「两种宿主（web / 桌面）」对比表：装插件、初始化 headless 档、`dshBin` 建议、QQ 投递方式；
- 非 Windows 用户明确：NapCat 基本只有 Windows 版 ⇒ 投递用 `qqBackend: onebot`；
- `lib/uvfetch.mjs` 补上 Intel Mac（`uv-x86_64-apple-darwin.tar.gz`），不再把 arm64 包装给 x64。
