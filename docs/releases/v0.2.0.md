# v0.2.0 — 用「领域」替代「保底组」

## 1. 要解决的问题

0.1.11 的保底组只解决**一类**内容被挤光的问题。再加一类就得再开一个字段，
代码里到处是「保底 / AIGC」这种二元判断。

2026-10-26 实测：`perDay=5` + 14 个关键词 ≈ 200 条候选抢 5 个位置。
搜「dsh 插件」时当天有好几条高度相关的新视频，正文里一条都没有 ——
不是没搜到，是「AIGC 日报」的评分表让非 AIGC 内容天然吃亏 + 位置只有 5 个。

⇒ 0.2.0 换成一个**开放集合**：领域。加一个领域不用改代码，每个领域自带保底位。

## 2. 数据模型

```json
"domains": [
  { "name": "AIGC", "keywords": ["ComfyUI", "LoRA"] },
  { "name": "dsh 插件", "keywords": ["dsh 插件", "DSH Harness"] }
]
```

- `name` 留空 ⇒ 显示时兜底成 `领域 N`（N 按位置，从 1 起）；
- `keywords` 为空的领域**视为无效**：不参与配额，也不算进「领域数 ≤ perDay」；
- `domains` 为空 ⇒ 退回旧行为（用 `keywords` / `guaranteeKeywords`），不报错。

### schema 的 volatile 规矩（这一条踩过坑，别再犯）

宿主的规则：**volatile 节点不能有 volatile 祖先；list / dict 的子节点永远算「被包住」**。
2026-10-27 另一个插件（dsh-cardcatalog v0.4.0）给 `tone` 的子字段多标了一次 volatile，
宿主直接拒掉整个 Config，插件连记忆目录都不注入。

所以这里：

```js
domains: z.array(z.object({
  name: z.string().default(''),
  keywords: z.array(z.string()).default([]),
})).default([]).extra('volatile', true),
```

**只有顶层 `domains` 标 volatile**；`name` / `keywords` / 里面的 `z.array(z.string())` 一律不标。

## 3. 配额规则

记 `N` = 有效领域数，`left` = 这一轮还能挑的 B站 条数。

1. `N > perDay` ⇒ 配置层先 clamp：只保留前 `perDay` 个，并 `warn`；面板在 `N >= perDay` 时禁用「+ 新增领域」。
2. 每个有效领域每轮**至少 1 条**，占用 `perDay` 总额度，不是额外加量。
3. 剩余名额 `left - N`（为正时）**纯按分数**从高到低填，不按领域加权、不轮流。
4. **归属唯一**：一条内容命中多个领域 ⇒ 按 `domains` 顺序算第一个，计数只算一次。
5. **空缺不许凑数**：某领域一条合格的都没有 ⇒ 正文空着，名额回流，并在「## 数据缺口」里写
   `领域「X」候选 N 条，全部不达标，原因：…`（候选是 0 也要写 0 是怎么来的）。
6. `left < N`（额度已经用掉一部分）⇒ 按顺序给前 `left` 个领域各 1 条，其余记 `「X」因本轮额度不足未挑`。

GitHub 侧**不强制**每领域 1 条（`perDay` 同时卡两边，强制会挤掉 B站 的保底位），
但 GitHub 条目也要标 `- 分组：<领域名>`（都不命中写「其他」）。

## 4. 提示词渲染

`lib/prompt.mjs` 新增 `renderDomainBlock(domains, perDay, left)`，四个分支都有明确文案：

| 情况 | 文案落点 |
|---|---|
| 无有效领域 | `（这一轮没有分领域，所有关键词统一排序。）` |
| `left < 1` | 名额用完 ⇒ 各领域保底位本轮都不挑，只在数据缺口里写一句 |
| `0 < left < N` | 前 `left` 个领域各 1 条，其余写「额度不足未挑」 |
| `left >= N` | 每领域 ≥1 条 + 剩余纯分数 + 归属唯一 + 空缺回流 + 领域清单逐条列出 |

模板占位符：`prompts/brief-prompt.txt` 里的 `{{GUARANTEE_BLOCK}}` 改成 `{{DOMAIN_BLOCK}}`；
渲染器**两个都填**（值相同）⇒ 手改过旧模板的用户升级后不会漏规则。
`scripts/audit-config.mjs` 把 `GUARANTEE_BLOCK` 列为例外别名（填了但模板里没有，不算死代码）。

## 5. 旧配置迁移

- `domains` 为空、旧字段非空 ⇒ `keywords` 变成「默认」领域，`guaranteeKeywords` 变成「保底」领域；
- 迁移是**只读**的：不写回配置文件，只在 `duty.log` / `/status`（`domainsMigrated`）里说一声；
- 用户下次在面板保存时才落盘成 `domains`，同时把旧的 `keywords` / `guaranteeKeywords` 置空；
- 搜索关键词 = 旧 `keywords` ∪ 各领域关键词（否则领域里的词根本不会被搜到）。

⚠️ 新键同时加进了 `DEFAULTS`、`CFG_PATCH_KEYS`、HTTP 白名单和工具描述 ——
这是 0.1.11 `guaranteeKeywords` 那次的教训（漏一处就会被 normalize 静默丢掉）。

## 6. 面板

「关注什么」下面原来两个输入框换成一个领域编辑器：

- 每个领域一行：`[领域名] [关键词多行] [删除]`，下面一行灰字「这个领域每轮至少占 1 条名额」；
- 关键词仍然**一行一个，不按逗号拆**（历史上逗号会把两条词粘成一条）；
- 底部「+ 新增领域」：有效领域数 >= `perDay` 时禁用，旁边写「每天最多挑 N 条 ⇒ 最多 N 个领域」；
- 顶部额度徽章那行：领域数超过剩余额度时补一句「本轮额度不足，后面的领域这轮拿不到保底位」；
- 保存走 `patch({ domains, keywords: [], guaranteeKeywords: [], workspace })`，一次写清。

## 7. 体检与测试

`scripts/audit-config.mjs` 新增三条 warn（拿 `examples/dsh-config.example.json` + 本机真实配置跑）：

1. `domains.length > perDay` ⇒ 报出来（说明会截断）；
2. 领域名为空 ⇒ 提示会兜底成 `领域 N`；
3. 同一个关键词出现在两个领域 ⇒
   `关键词「X」在领域 A / B 重复；归属永远算第一个，B 里的这个词等于没用`。

`scripts/prompt-smoke.mjs` 的 F 段重写成领域断言（四个分支、两个占位符内容相同、迁移、clamp、清洗）；
`scripts/smoke-apply.mjs` 新增 [7/7]：保存 `domains` 后读回、旧字段清空、超 `perDay` 截断且 `warn`。

## 8. 升级注意

- 老配置不用动：第一次跑会被迁移成领域，面板里确认一下再保存即可；
- `perDay` 仍是 B站 / GitHub **各自**的硬上限，语义没变；
- 领域数就是 `perDay` 的天然上限：想多放几个领域，先把 `perDay` 调大。
