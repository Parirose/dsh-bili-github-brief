# v0.1.9 — 面板文案对齐 / 配置文档补全 / 降级与 profile 报错 / 两个新自检

这一版没有改任何“跑一轮”的行为（除了两处新增的**提前报错**），主要是把
“选项存在、UI 也在、某条分支却不读它”这一类问题清掉，并把它们变成能自动检查的东西。

## 1. 面板定时开关按模式置灰（行为零变化）

`tick()` 里两套调度是**互斥**的，但面板两段都无条件渲染：

- 日报模式 ⇒ 只看 `scheduleEnabled` / `scheduleTime`；`peakValley` / `noon` / `night` 不生效
- 非日报模式 ⇒ 只看峰谷窗口；`scheduleEnabled` / `scheduleTime` 不生效

现在：对应的开关直接**置灰**，note 改成实话；`status().nextRunAt` 在非日报模式下为 `null`
（避免显示一个根本不会发生的“下次运行”）。

> 这个提交只动了 `client.js` 文案/`disabled` 与 `index.js` 的一个字段，**没动 `tick()`**。

## 2. 配置文档补全（schema 35 键 ↔ 文档 35 行）

`docs/CONFIG.md` 补上 13 个漏掉的键：`peakValley` `noon` `night` `autoComment` `mentionName`
`replyToComments` `replyPerRound` `commentPerRound` `dmUid` `pythonPath` `dshBin` `headlessProfile` `overlayMcp`。

新增两节：

- **「会对外发东西的开关」** —— 评论 / 私信 / QQ 群消息，写清楚“这不是只影响本地报告”
- **「调度：两套窗口互斥」** —— 与第 1 条的面板文案一致

## 3. `overlayMcp` 关掉时要有红字

`overlayMcp=false` ⇒ 那一轮根本没挂 MCP ⇒ 0 个工具、报告必空。这个开关面板里没入口，
“关了忘了”能一直存在。现在 `status()` 返回：

```json
{ "mcpOverlay": false, "degraded": ["mcp-off"] }
```

面板在顶部出红字。只提示：**不自动改回 true、也不阻止跑**（排障时允许故意关）。

## 4. `headlessProfile` 不存在时先报错

以前是子进程吐一句英文 `profile "xxx" not found`，落进 `duty.log` 像乱码。
现在跑之前先查 `$DSH_HOME/profiles/<name>`，不存在就直接返回中文错误（不 spawn）：

```text
这一轮没跑：profile「nope」不存在（应在 C:\Users\xxx\.dsh\profiles\nope）。
把设置里的「headless profile」改成已存在的档，或先用官方 CLI 建一个。
```

## 5. 新自检：`scripts/prompt-smoke.mjs`（这一批里唯一真正防回归的）

把渲染抽成纯函数 `lib/prompt.mjs` 的 `renderBriefPrompt()`，`index.js` 改成调用它。
然后四条断言（sentinel = `ATRI_SENTINEL_9f3`）：

| # | 场景 | 断言 |
|---|---|---|
| A | 正常模板 + ownerBlock | 含 sentinel，且无残留 `{{X}}` |
| B | ownerBlock 为空 | 不会凭空出现 sentinel，也不崩 |
| C | 旧模板（无 `{{OWNER_DOC}}`） | 人设被追加到**末尾** |
| D | 空模板 | 走兜底文案，且人设不丢 |

验证断言真的能抓住：把 `lib/prompt.mjs` 里“追加 ownerBlock”那行注掉 ⇒ **C/D 立刻变红**；
恢复后四条全绿。

```powershell
node scripts/prompt-smoke.mjs
```

## 6. 新得体检：`scripts/audit-config.mjs`（默认只警告）

四项检查：

- schema 每个键在 `index.js` 里至少有 1 处消费点（含动态 `for (const k of ['noon','night']) { cfg[k] }`）
- 模板 `{{X}}` ↔ `fill('X')` 双向齐
- `client.js` 的 API 调用 ↔ `index.js` 的 `path === '...'` 路由
- 每个 schema 键都带 `.extra('volatile')`

```powershell
node scripts/audit-config.mjs            # 只打印 ⚠️，退出码 0
node scripts/audit-config.mjs --strict   # 有 ⚠️ 就退出码 1
```

当前代码：**0 条 ⚠️**（schema 35 键全覆盖，noon/night 不算死键）。
已挂进 `.github/workflows/ci.yml`（非 strict）。

⚠️ 它**防不了** 0.1.8 那种 bug（变量有消费点、但消费在另一条分支）—— 那种只能靠第 5 条。
