# v0.1.1 — 桌面版（Electron）修复

这是修复版，针对 DSH NEXT 0.2.1-rc.2 / Electron 44 上安装后插件不激活的问题。

## Fixed

- 桌面版（DSH NEXT / Electron）装完不激活：`cordis.patch.yml` 的 `name` 与包名不一致
  - 原来的 `name: dsh-bili-scroll` 会导致 `ERR_MODULE_NOT_FOUND`
  - 现在改为 `name: dsh-bili-github-brief`
  - `id: bili-scroll` 保持不变，settings 仍按命名空间绑定
- 桌面版取不到宿主 `schemastery` / `dsh-tools`：宿主包在 `app.asar` 内
  - `candidateRoots()` 现在会从 `process.resourcesPath` / `process.execPath` 推导 asar 路径
  - asar 中找不到时仍按原逻辑回退，不影响普通 web profile
- 更新检查与一键升级指向本项目自身，而不是上游仓库

## Added

- `scripts/verify-host.mjs`：装后自检
  - 包名一致性
  - 挂载 `id` 与 `export const name` 一致性
  - `schemastery` / `dsh-tools` 是否从宿主树取到
- `docs/INSTALL.md`：桌面版安装路径、headless profile 前置条件、宿主依赖自检

## 安装 / 升级

### DSH 桌面版（Electron）

桌面版没有 `web` profile，且 `desktop` profile 由 Electron 应用管理。使用应用自带的 headless adapter：

```powershell
$env:ELECTRON_RUN_AS_NODE = '1'
& 'C:\DSH NEXT\DSH NEXT.exe' 'C:\DSH NEXT\resources\app.asar\lib\plugin-cli.js' `
  desktop add "link:D:\path\to\dsh-bili-github-brief"
```

装完重启 DSH NEXT。

第一次跑一轮前，先初始化 headless profile：

```powershell
& '<app>/DSH NEXT.exe' '<app>/resources/app.asar/lib/plugin-cli.js' headless list
```

### 标准 web profile

```bash
dsh plugin --profile web add github:Parirose/dsh-bili-github-brief
```

装完重启 DSH。

### NapCat 插件

下载本 Release 的：

```text
napcat-plugin-dsh-bili-forward-v1.0.0.zip
```

解压到：

```text
<NapCat>/plugins/napcat-plugin-dsh-bili-forward/
```

然后在 NapCat 插件配置里填写群号、私聊 QQ、token，并确认 `forwardBriefs: true`。

## 验证

在插件目录运行：

```powershell
node scripts/verify-host.mjs
```

桌面版用 Electron 再跑一次：

```powershell
$env:ELECTRON_RUN_AS_NODE = '1'
& '<app>\DSH NEXT.exe' scripts\verify-host.mjs
```

期望看到：

```text
schemastery 取到了（Config 可用，设置页正常）
dsh-tools 从宿主树取到（用的是宿主的 defineTool）
结果：全部通过
```
